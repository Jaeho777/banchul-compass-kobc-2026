# Codex 작업 지시 — 2026 KOBC 「반출나침반」 출품 최종화

## 역할·절대 목표
당신은 2026 한국해양진흥공사 해운·항만·물류 AX 혁신 아이디어 공모전의 최종 제출물을 완성하는 개발자 겸 실무 검증자다. 이 ZIP에 포함된 다섯 산출물을 먼저 열어 분석한다. 새 아이디어를 무작정 발명하지 말고 **「반출나침반」**을 출품 가능한 상태로 고도화한다. 실제 접수까지 연결되는 필수 서류 확인이 최우선이다.

**오늘 2026-10-30 14:00 KST 마감.** 기능을 늘리느라 제출 마감을 놓치지 마라. 먼저 공식 서식과 필수 파일을 확보·완성한 뒤 가능한 범위에서 데모를 손본다. 사용자가 마지막 로그인 및 업로드를 수행해야 한다. 제출하지 않은 상태를 제출완료라고 기록하면 안 된다.

- KOBC 공식 공고: https://www.kobc.or.kr/ebz/kor/bbs/view.do?bIdx=98040&mId=0505010000&ptIdx=241
- AX/DX 공고: https://kobcax.com/notice/공지-2026-해운·항만·물류-ax-혁신-아이디어-공모전/
- 온라인 접수: https://kobcax.com/contest/
- 공식 공고에는 `붙임3. 참가신청서 등 일체 서류.hwp`가 있으며, 원본 지정 양식과 서명/동의 항목을 실제 확인해야 한다. 공고에 적힌 마감은 2026-10-30 14:00 KST, 방법은 **사이트 회원가입·로그인 후 게시물 작성**이다. 방문·이메일 접수는 불가하다.
- 지정 HWP 원본을 다운로드할 수 없다면 없는 서류를 제작했다고 주장하지 말고, 사용자에게 필요한 다운로드/첨부 액션을 최상단에 보여라. 임의 양식으로 완전 대체하지 않는다.

## 기존 출품안 — 보존할 포지셔닝
- 이름은 오직 **반출나침반**. DemurZero, Zero 등 과거 이름은 최종 산출물에서 제거.
- 대상: 중소 포워더/화주 물류 운영자.
- 문제: 컨테이너별 LFD(Last Free Day), 통관·서류·트럭 배차 등의 이벤트가 흩어져 있어 비용 발생 전 우선 조치를 놓치기 쉽다.
- 제안: 컨테이너별 이벤트 출처와 계약별 기준을 대조 → 위험·모의 비용 노출 표시 → 근거 확인 → 승인/보류/조치완료 이력 → 사후 검토.
- 출품자: 이재호, 한동대학교 AI융합·경영 복수전공, 개인 출품.
- 실제 경험: 2026.07–08 AI 인턴에서 패션 315 SKU × 155주 수요예측 실험, WAPE 64.15%→59.57%; 사후분석 기능 제안 및 승인 후 개발·테스트. 해운 현장 검증 성과와 혼동하지 않는다.

## 매우 중요한 사실/용어 잠금
1. 기존 HTML은 **가상 데이터 + 규칙 기반 계산 + 클릭 가능한 UI**다. 학습한 예측모델, 항만·선사 실시간 연동, 실제 비용 절감, 실제 기업 파일럿이 없다. 화면/문서/영상에 반드시 표시.
2. demurrage / detention / terminal storage 및 free time의 적용 주체·계약·지역·요율·휴일 규정은 다를 수 있다. 지금은 **'무료기간 초과 위험 및 비용 노출의 시나리오'**를 목표로 하며 임의 단일 요율을 실제 계약 요금으로 제시하지 마라.
3. LFD가 확인되지 않거나 통관/트럭 예약 일정이 없으면 '확인 필요'로 처리한다. 숫자 0이나 임의 요율로 결측을 덮지 마라.
4. 제안서의 `월 120건 × 초과노출 15% × 예방가능 25% × 평균 16만원 = 월 72만원`은 **가정 시나리오**다. 4.5건은 기대값이며 실제 4.5건을 예방했다는 뜻이 아니다. 실적·ROI로 표현하지 않는다.
5. AI 모델 구현은 유효한 과거 운영 이력 확보 뒤의 **2단계 계획**이다. 지금은 가상의 규칙형 PoC이며 'AI 실제 예측 성능'을 만들어내지 마라.
6. 소유권 없는 운영 데이터·고객사 계약서·키·개인정보를 수집하거나 무단 업로드하지 않는다. 입항/통관/운송 일정은 승인된 CSV 또는 사용자가 제공한 합성 샘플로만 처리한다.

## 수행 순서 (마감 보호, 우선순위 강제)

### P0: 즉시, 공식 제출 형식/서류 확보
- 공고 원문과 첨부 HWP를 확인하고 참가신청서/아이디어 제안서/동의서/서명/쪽수/파일 형식/용량/ZIP 허용 여부를 체크리스트로 만든다. 공식 조건이 기존 자료보다 우선.
- 첨부된 DOCX를 바탕으로 지정 양식에 들어갈 내용을 **바로 붙여넣거나 옮긴 최종 제안서**를 만든다.
- 현재 원고의 오타(`반출나침반는` 등)를 바로잡고 내용 분량·표 여백·한글 폰트 깨짐을 점검한다.
- 지정 양식 적용에 실패하면 제출자가 바로 복사할 수 있는 문항별 텍스트와 `필수 조치`를 제공하고 원본 지정 양식을 사용자에게 요청하는 방식으로 처리한다.
- 마감 전 중단 가능한 상태로 매 순간 제출 후보 파일을 유지하고, 고도화 때문에 기존 파일을 덮어쓰지 않는다.

### P1: 제안서 설득력 개선
- 누구의 어떤 비용·업무 위험을 줄이는가, 기존 엑셀/D-3 알림과 무엇이 다른가, 실제 의사결정이 어떻게 바뀌는가를 첫 페이지에서 명확히.
- 계층을 `입력 (이벤트/규정/출처) → 대조 및 보수적 위험 판정 → 조치 우선순위 → 사람의 승인 → 결과 이력`으로 정리.
- 효과성·실현가능성에 집중. 측정되지 않은 성과는 가정 및 향후 검증계획으로 명확히 구분.
- 구체 사례 2–3개, 데이터 필드 표, 계약별 요율 예외, 현장 승인 주체, 90일 PoC 검증 방식을 포함.
- 가능하면 심사 관점(실현가능성, 효과성, 적합성, 혁신성)별 대응 근거표를 만든다. 실제 공식 배점은 첨부 공고 원본 확인 후 반영하고 검증 전 임의 단정하지 않는다.

### P2: 현 HTML 데모는 '필요한 만큼만' 고도화
- 기본 구조/디자인이 있으므로 처음부터 React/SaaS 프로젝트로 갈아엎지 않는다. 오프라인 단일 HTML 실행을 우선.
- 입력 출처/최종 갱신일/모의 데이터 표시, 계약/LFD 미확인 시 보류, 상태별 우선순위, 실제 작업 가능한 승인·보류·조치완료 로그를 눈에 띄게 개선.
- 사용자 조작 후 위험·비용 요약과 내보내기가 일관되게 갱신되게 한다.
- HTML의 고정 데이터가 모두 합성 사례임을 워터마크/안내문으로 표기한다.
- 새 기능은 시간이 충분할 때만: CSV 샘플 import/export, D-3 알림 대비 차별성 시연, 상태 저장(localStorage) 등. 임의의 '학습한 AI' 기능은 만들지 않는다.
- 데모 완성도를 근거로 실무에서 비용이 절감됐다고 주장하지 않는다.

### P3: 재현성과 증빙
- 계약요율/반출예정/마지막 무료일이 확인된 사례, 결측 사례, 이미 반출 완료된 사례, 날짜 경계, 지연 시나리오를 최소 6개 테스트.
- 자동화 테스트가 가능하면 파일과 실행 명령을 남기고, 브라우저 화면을 캡처하여 PoC 증빙 PDF에 수록.
- 테스트 로그는 실행해서 확인한 것만 '통과'라고 써라.
- 개인정보, CSV 수식 인젝션, HTML 입력 검증 등의 기본 안전성 확인.

### P4: 최종 산출물 (서로 다른 목적별로 폴더 구분)
1. `submission/` — 공식 필수 양식을 적용한 실제 업로드용 문서 파일. 지정 양식 미확보 시 `DRAFT_NOT_OFFICIAL` 표기.
2. `supplement/` — 고도화된 오프라인 데모(HTML), 화면 캡처, 1–2쪽 PoC 사실검증 설명.
3. `sources/` — 원본 산출물. 수정 과정에서 원본 보존.
4. `QA_REPORT.md` — 변경 내역, 확인된 테스트, 미검증 주장, 누락 서류, 검수 결과.
5. `SUBMIT_NOW.md` — 사이트 로그인부터 최종 확인까지 **사용자가 해야 할 최소 단계**를 5~8줄로 요약. 마감시각을 첫 줄에.

## 보고 형식
긴 설명보다 실제 경로/파일명/미완료 항목을 먼저 출력하라. 예:
- `✅ 준비됨`: [실제 파일 경로]
- `⚠️ 사용자 조치`: 공식 HWP 서명/동의/게시물 제출/등록 확인
- `❌ 미검증`: 실제 항만 데이터, 운영 비용 절감, ML 정확도

'완성', '접수완료', '실증성공'은 실제 근거와 파일이 있을 때만 사용한다. 지금 즉시 파일을 확인하고 **P0부터 실행**하라. 내가 이미 요청한 일이므로 코드 편집과 파일 제작을 위해 추가적인 동의를 요구하지 마라.
