개인정보·동의·서명은 사용자가 공식 서식에서 작성.

## 1.1 핵심내용 요약

반출나침반은 중소 포워더·화주의 수입 컨테이너 담당자가 ‘오늘 무엇부터 확인하고 조치할지’를 정하는 승인형 업무 도구다. 계약상 마지막 무료일(LFD), 통관·반출가능·트럭 예약 일정을 대조하여 확인 필요 건과 비용 노출 건을 나누고, 근거 확인부터 담당자 승인·사후관리까지 연결한다. 기존 엑셀·TMS에 보조 계층으로 도입한다.

## 1.2 배경 및 필요성

무료기간은 계약마다 다르고, 통관·운송 일정은 서로 다른 담당자에게 흩어져 있다. 단순 D-3 알림만으로는 기한이 남아 있어도 이미 초과가 예상되는 건과, 기한이 임박했지만 반출을 끝낸 건을 구별하기 어렵다. 초기 적용 범위는 수입 컨테이너의 터미널 반출 전 업무로 한정한다.

## 1.3 활용 Scene 및 기술

오전 담당자는 미확인 계약·예약을 보완하고, 계약별 계산 규칙과 일정에 따른 초과일수·모의 비용을 비교해 조치를 승인한다. 입력 출처, 판단 근거와 상태변경을 기록하고 실제 반출·정산까지 확인한다. CSV 입력·출력, JSON 백업·복원, 브라우저 저장을 포함한 단일 HTML을 제출한다. 모든 데이터는 합성이며 학습모델·실시간 연동은 없다.

## 1.4 기대효과

목표는 확인 누락과 불필요한 알림을 줄이고 반출 지연 대응 시간을 단축하는 것이다. 월 120건×초과노출 15%×예방가능 25%×건당 16만원=월 72만원은 비용을 차감하지 않은 가정 편익이며 실적이 아니다. 90일 PoC에서 고정 D-3 알림과 동일 사건·동일 시점으로 비교하여 도입 여부를 결정한다.

## 2.1 문제 정의 / 적용 대상

초기 사용자는 여러 선사·터미널의 수입 컨테이너를 관리하는 중소 포워더 또는 화주의 물류담당자다. 일일 운영자는 기한과 진행 상황을 대조하고, 팀장은 추가 운송비·업무 조정의 승인권을 가진다. 통관사·운송사는 확인된 상태를 제공한다. 특정 기업의 참여나 현장 인터뷰 완료를 전제로 하지 않는다.

핵심 문제는 날짜를 잊는 것만이 아니다. 계약별 무료기간과 통관·반출가능·운송 예약 중 어느 정보가 누락됐는지, 그 누락을 누가 해결해야 하는지까지 연결되지 않는 것이 제품 가설이다. 첫 PoC에서는 운영자 인터뷰와 실제 기록으로 이 가설부터 확인한다.

범위는 한 협력 포워더, 한 수입 업무, 승인된 계약 규칙으로 제한한다. demurrage, detention, terminal storage를 동일한 요금으로 합치지 않는다. 공컨테이너 반납까지의 detention 최적화, 자동 배차, 선사·터미널 정산 확정은 초기 범위 밖이다.

엑셀·TMS | 익숙한 원장과 실행 업무 | 결측·불일치 확인 대기열, 승인 이력
고정 D-3 알림 | 기한 접근을 간단히 전달 | 기한 전에도 일정상 초과가 보이면 우선 노출
선사·터미널 조회 | 상태·규정 확인의 원천 | 여러 건의 비용 시나리오와 후속 조치 연결

## 2.2 접근 방식 / 핵심 아이디어

입력과 출처 확인 → 계약 기준 대조 → 확인 필요 건 및 비용 노출 건 정렬 → 담당자 승인 → 업무완료 기록 → 실제 반출·정산 확인의 순서로 운영한다. 금액보다 ‘판단할 수 있는 정보가 있는가’를 먼저 확인한다. 자동 승인이나 자동 반출 지시는 하지 않는다.

LFD, 계약·요율 또는 통관·터미널 반출가능·트럭 예약 일정 중 필수 값이 없으면 ‘확인 필요’로 남긴다. 비용 미상은 0원이 아니다. 확인된 건의 예상 반출일은 세 일정의 최댓값이며, 기준일보다 과거인 미완료 일정은 갱신을 요구한다. 승인 후 입력 또는 지연 가정이 바뀌면 기존 승인을 무효화하고 재검토한다.

제출 프로그램에서 달력일, 주말·지정 휴일을 제외한 영업일, 2개 구간요율을 선택하여 계산한다. LFD 당일은 무료이고 다음 날부터 과금하는 모의 계약이다. 달력일 초과일수=max(0, 예상 반출일−LFD)이며, 영업일은 해당 구간의 주말·휴일을 제외한다. 구간요율은 1구간 적용일수까지 기본요율, 이후 일수에는 2구간요율을 적용한다. 실제 계약의 복합 과금·마감 시각·통화 변환은 지원하지 않으며 적합성이 확인되지 않으면 승인하지 않는다.

정렬은 확인 필요 건을 우선 확인 대상으로 분리한 뒤, 산정 가능 건을 초과일수 위험군과 노출액 내림차순으로 보여준다. 노출액 합계는 산정 가능 미반출 건만의 부분합임을 표시한다. ‘조치완료’는 연락·배차 확인 등 업무 수행의 기록이며 위험 해소를 뜻하지 않는다. 실제 반출일이 기록되어야 미래 노출에서 제외하고 사후 정산 대상으로 이동한다.

차별화 가설은 독점적인 예측 알고리즘이 아니라 계약·이벤트 근거와 인간 승인, 사후 결과를 하나의 사건 이력으로 연결하는 데 있다. 기존 상용 TMS에 유사 기능이 없다고 주장하지 않으며, 현행 엑셀·D-3 방식 대비 운영자 시간과 오류 감소를 검증한다.

## 2.3 활용 시나리오 및 화면 구성

모든 사례의 기준일은 2026-10-30이며 합성 데이터다. 화면 상단에는 모의 검증 표시, 위험 건수, 산정 가능한 비용 부분합, 미확인 건수와 검토 이력을 둔다. 목록에서 컨테이너를 선택하면 계약·이벤트 출처와 갱신일, 산정 근거, 담당자 조치 입력이 열린다.

사례 A CNT-104: LFD는 10/31이나 트럭 예약이 없다. 반출일·비용을 임의 추정하지 않고 확인 필요로 표시하며 승인을 막는다. 담당자가 예약일 10/31을 입력하면 재판정 후 승인할 수 있다. D-3 경보와 달리 해결할 결측 항목이 명확하다.

사례 B CNT-505: LFD 11/03, 통관·배차 중 최종 일정 11/05로 2일 초과가 예상된다. 모의 일요율 20만원에 따라 40만원의 시나리오 노출을 표시한다. 기한이 4일 남아 D-3 알림 범위 밖이어도 확인·조치를 시작한다. 실제 계약 청구액이 아니다.

사례 C CNT-311: 10/30 실제 반출 완료가 확인된 합성 사례다. 추가 지연 슬라이더를 움직여도 미래 노출은 발생하지 않는다. 실제 정산 입력이 없으면 비용 절감이나 정산 완료로 표시하지 않는다.

시연 순서: 기본 화면의 미확인 3건과 비용 부분합 58만원 확인 → CNT-104 예약일 보완 → 담당자·사유를 입력해 승인 및 조치완료 → CNT-808 실제 반출·모의 정산 입력 → 지연 2일 가정 시 재검토 확인 → CSV 내려받기·재입력 → JSON 백업·복원. 초기화로 합성 초기 상태를 복구한다. 브라우저 저장을 지원하며 JSON 복원·입력 변경 시 미반출 건은 재승인을 요구한다. 저장 파일은 인증된 감사로그가 아니다.

## 2.4 AI/데이터 활용 및 구현 구조

현재 제출물은 오프라인 단일 HTML에서 규칙 추론·시나리오 분석·의사결정 이력까지 실행한다. 컨테이너별 입력 편집, 달력일·영업일·구간요율 계산, 미확인 승인 차단, 재승인, 반출·정산 비교, CSV 입력·출력, JSON 백업·복원, 브라우저 저장을 구현했다. 외부 API·서버·학습모델·인증 계정은 없다. 개인정보나 고객사 계약정보는 입력하지 않는다.

판단 엔진은 명시적인 계약 규칙과 이벤트를 대조하는 결정 지원 방식이다. 학습된 AI의 확률 예측을 대신했다고 주장하지 않는다. 추론 근거는 입력 필드·누락 항목·비용 산식으로 재현할 수 있고, 결과가 바뀌면 담당자가 다시 승인한다. 사용자는 판단을 보류할 수 있으며 자동 반출·배차 명령을 집행하지 않는다.

AI 전환 관점의 제안 가치는 흩어진 업무 데이터를 구조화하고 설명 가능한 판단·승인·결과를 연결하는 데 있다. 제출 시점의 작동 범위와 미검증 범위를 구분한다. 실제 항만 이력이 없으므로 학습모델, 초과 확률, 예측 정확도, 현장 비용 절감 성과는 제시하지 않는다. 합성 데이터로 학습한 모델을 실데이터 예측모델처럼 포장하지 않는다.

## 2.5 실행 계획

제출 시점에 입력부터 사후 정산까지 전체 시연 흐름을 구축한다. 90일 계획은 기능 구현을 미루는 일정이 아니라 현장 유효성을 확인하는 검증 일정이다. 협력사 확보 후 계약 책임자 1명, 운영자 1명, 개발자 1명이 승인된 기록을 기존 업무와 병행 대조한다. 협력사 참여나 실데이터 연계는 현재 확보된 사실이 아니다.

초기 예산은 견적이 아닌 의사결정용 가정이다. 개발 20인일×30만원=600만원, 현장 검토 5인일×30만원=150만원, 보안·테스트 3인일×30만원=90만원, 운영 도구 30만원, 예비비 87만원으로 총 957만원(부가세·상용 API 비용 별도)을 가정한다. 이재호 단독 개발과 협력사 검토 시간을 구분해 관리한다. 기존 시스템 통합·규정 추가로 비용이 늘 수 있다.

제안자는 2026.07~08 AI 인턴에서 패션 315 SKU×155주 수요예측 실험과 사후분석 기능 제안·승인 후 개발·테스트를 수행했다. 제공된 이력 기준 WAPE 64.15%→59.57%이며 해운 데이터 성과가 아니다. 해당 경험을 오류 분석과 승인 흐름 설계에 활용하되, 해운 계약 규정 검증은 현장 책임자와 함께 수행한다.

## 2.6 기대효과 및 성과 지표

정량 효과는 현재 미측정이다. 기준 시나리오는 월 120건×초과노출 15%×예방가능 비율 25%×건당 회피가능 비용 16만원=월 72만원, 연 864만원의 총편익이다. 4.5건은 기대값이지 실제 예방 건수가 아니다. 예방가능 비율과 비용은 검증되지 않은 가정이다.

예방가능 비율을 10%·25%·40%로 바꾸면 월 총편익은 각각 28.8만원·72만원·115.2만원이다. 월 운영비 20만원과 추가 업무 5시간×2만원을 가정하면 순편익은 각각 −1.2만원·42만원·85.2만원이다. 초기 957만원을 기준 순편익으로 회수하는 단순 기간은 약 22.8개월이며 세금·할인율·확산비용을 반영하지 않았다. 초기 개발비를 여러 고객이 나눠 부담할 수 있는지 검증해야 한다.

## 2.7 리스크 및 대응 방안

무료기간·요율·휴일 규정 오류가 가장 큰 운영 위험이다. 제출 프로그램은 달력일·영업일·2구간요율을 구현했지만 실제 계약의 모든 조항을 포괄하지 않는다. 적용 주체·비용 종류를 구분하고 계약 책임자가 규칙 적합성을 확인해야 한다. 날짜 단위 시연은 시간대별 터미널 마감과 복합 요율을 검증하지 않았으므로 실운영 배차 판단에 바로 사용하지 않는다.

데이터 확보 전 고객사 계약서나 개인정보를 임의로 수집하지 않는다. PoC에서는 제공 동의, 최소수집, 역할별 접근권한, 보유기간과 파기 절차를 합의한다. 상용 승인·감사로그에는 서버 인증과 변경 통제가 필요하며 현재 브라우저 입력 이름은 인증된 신원이 아니다.

잘못된 입력과 규칙 오판은 경보 원인·원천 갱신일을 보여주고 담당자가 보류할 수 있게 관리한다. 입력 수정·지연 가정 변경·JSON 복원 시 재승인을 요구하며, 업무완료와 실제 반출·정산을 구분한다. CSV 수식 인젝션 방어, JSON·CSV 검증과 텍스트 전용 DOM 렌더링을 적용한다. 브라우저·백업 파일을 수정할 수 있는 사용자를 막는 운영 보안은 제공하지 않는다.

규칙형 시연의 작동은 실제 비용 절감 또는 항만 실증의 증거가 아니다. 기존 상용 솔루션 전수 비교, 현장 데이터 연계, 학습된 AI 정확도, 운영 보안 인증은 미검증이다. 후속 PoC에서 이 항목들을 확인하고 목표 미달이면 도입을 유보한다.
